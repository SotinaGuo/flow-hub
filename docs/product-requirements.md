# 通用申请流程 MVP 产品需求

## 目标

实现一个通用的内部申请流程，使用 Mock 数据模拟课程、人员、部门等基础数据，验证从发起申请到查看结果和统计分析的完整闭环。

## 支持的申请类型

第一版支持三种申请类型：

1. 请假
2. 报销
3. 加班

三种类型共用申请流程，通过类型配置区分表单字段。第一版不实现用户自定义申请类型，但数据模型需要保留后续配置化扩展能力。

## 功能需求

### 发起申请

- 用户选择申请类型。
- 填写申请人信息和申请内容。
- 请假包含假期类型、开始时间、结束时间和事由。
- 报销包含报销类型、金额、发生日期和事由。
- 加班包含加班日期、开始时间、结束时间和事由。
- 表单需要进行必填和基本格式校验。

### 预览与修改

- 填写完成后可以预览申请信息。
- 预览页需要区分申请人信息和申请内容。
- 用户可以返回对应表单修改后再次预览。
- 确认提交后生成申请记录并进入待审批状态。

### 申请列表

- 展示申请编号、申请类型、申请人、提交时间、金额或时间范围、当前状态。
- 支持按申请类型和状态筛选。
- 支持进入申请详情。
- 需要处理有数据、无数据和筛选无结果状态。

### 申请详情

- 展示完整申请人信息和申请内容。
- 展示申请状态和状态变化信息。
- 待审批申请可以模拟通过、驳回或撤回操作。
- 已完成状态需要展示清晰的结果反馈。

### 状态流转

```text
草稿 -> 待审批 -> 已通过
              -> 已驳回
待审批 -> 已撤回
```

非法状态转换不得执行，并需要向用户提供明确反馈。

### 统计报表

- 展示申请总数、待审批数、已通过数和已驳回数。
- 展示不同申请类型的数量分布。
- 使用 Apache ECharts 展示至少一个状态分布图和一个类型分布图。
- 图表需要处理加载、无数据、窗口尺寸变化和销毁场景。

## 非功能需求

- 使用 TypeScript、SvelteKit、Tailwind CSS、Vitest 和 Apache ECharts。
- 禁止使用 React、Vue 和 Angular。
- 课程、人员、部门及申请记录使用本地 Mock 数据。
- 组件需要具备单元测试。
- 页面应具备响应式布局、清晰的信息层级和完整的交互状态。
- 代码应易于将 Mock Repository 替换为真实 API。
